# Tax Perks — Spec

**Hackathon:** Cursor Hackathon Berlin @ Taxfix, 2026-09-17. Challenge "Tax 365": voluntary, recurring engagement with Taxfix outside filing season.
**Deadline:** 21:00 video upload. Scope everything to a 90-second demo.

## 1. Vision

A tax-perk assistant that turns the perks a user is already entitled to into **goals they can see, track and document all year** — so nothing is lost by July.

Users should feel *in control, financially savvy, a little bit clever*. Never dutiful, anxious or guilty.

## 2. Non-goals (hard)

- No streaks, points, badges, leaderboards, countdown timers. (Judges disqualify "manipulative streaks" and "fake urgency".) Progress is always **euros toward a real statutory cap**.
- No push notifications in the demo.
- No real tax filing, no ELSTER, no real auth. One seeded user.
- No general perk catalogue browsing. The user only ever sees perks recommended for them.
- No exact tax computation. Every number is labelled *estimate*.

## 3. Seeded user (the only user)

```json
{
  "id": "u1",
  "name": "Lena",
  "city": "Berlin",
  "taxYear": 2026,
  "employment": "employee",
  "grossIncome": 58000,
  "marginalRate": 0.35,
  "commuteKm": 18,
  "workDaysPerYear": 220,
  "homeOfficeDaysPerYear": 90,
  "housing": "renter",
  "children": [{ "age": 6 }],
  "married": false,
  "hasCleaner": true,
  "hasPrivateSchool": false
}
```

Everything in this profile is "what Taxfix already knows from last year's filing".

## 4. User stories + acceptance criteria

### S1 — Relevant perks only
*As a user, I get perks recommended from what Taxfix already knows about me, so I never scroll a list of all perks.*

- Home screen shows **at most 3** perk cards, ranked by estimated € value for this user.
- Each card: perk name, one-line why-you ("You have a cleaner"), estimated max € back, `Set as goal` button.
- Cards come from the recommender agent (§6.1) using the seeded profile; perks not matching the profile never appear.

### S2 — Pick a goal
*As a user, I choose a tax-saving category as a goal for the year, so I can see my progress toward it.*

- Tapping `Set as goal` creates a Goal: `{perkId, targetEur (= perk cap for this user), securedEur: 0, documents: []}`.
- Goal screen shows a progress bar: `securedEur / targetEur`, in euros, with the cap named ("€4,000 max credit").
- Copy under the bar states the rule in one sentence ("20% of labour costs back if paid by bank transfer with an invoice").
- Multiple goals allowed; home screen lists active goals above remaining recommendations.

### S3 — Capture as you go
*As a user, when I reach a milestone I attach the invoice/receipt right there, so the evidence is already collected when filing starts.*

- Goal screen has `Add document` (file upload or paste text).
- Document agent (§6.2) returns `{vendor, date, amountEur, labourEur, paidByTransfer, category, confidence}`.
- If `paidByTransfer == false` for a §35a perk → card shows **"Paid in cash? This one won't count — pay by transfer next time"** and secured € does not increase. This is the "honest" moment of the demo; keep it.
- Otherwise `securedEur += benefit(document)` per §7 and the bar animates.
- Document is listed under the goal with amount and status (`counted`, `not counted: cash`, `needs review`).

### S4 — Year-end moves (stretch, only if S1–S3 are demoable by 20:15)
- A "Before Dec 31" card lists up to 3 moves with € values, from the planner agent (§6.3): e.g. "Pay your Handwerker invoice by transfer this year: +€240", "File your 2022 return before it expires: ≈ €1,000".

## 5. Screens (phone width, one column)

1. **Home** — header "Your 2026 refund so far: **€ N** (estimate)"; active goals (progress bars); recommended perks (≤3 cards).
2. **Goal** — perk name, rule sentence, progress bar with cap, document list, `Add document`.
3. **Add document** — file input + textarea; shows agent result and `Counted / Not counted` before returning.

Header number = sum of `securedEur` across goals + baseline (Pauschbetrag effects are ignored; keep it simple).

## 6. Agents (the orchestration story — screenshot this for the pitch)

All agents are LLM calls with structured JSON output. Perk rules come from `perks.json` (§7) and are **never** generated by the model.

### 6.1 Recommender
- Input: profile, `perks.json`.
- Output: `[{perkId, whyYou, estimatedMaxEur}]`, max 3, sorted by `estimatedMaxEur` desc.
- Rule: a perk is eligible only if its `eligibility` predicate matches the profile (evaluated in code, not by the model). The model writes `whyYou` only.

### 6.2 Document agent
- Input: uploaded file (image/PDF) or pasted text; the goal's `perkId`.
- Output: `{vendor, date, amountEur, labourEur, paidByTransfer: true|false|unknown, category, confidence}`.
- `paidByTransfer` is inferred from words like "Überweisung", "bar", "cash", IBAN present. `unknown` → status `needs review`.

### 6.3 Planner (stretch)
- Input: profile, goals, today's date.
- Output: `[{title, whyNow, estimatedEur, deadline: "2026-12-31"}]`, max 3.
- Only from a fixed list of `moves` in `perks.json`; the model ranks and phrases, never invents.

## 7. Perks data (`perks.json`) — fixed, do not let the model edit

| id | name | type | rate | cap (benefit €) | eligibility |
|---|---|---|---|---|---|
| household_services | Household services (cleaning, gardening, care) | credit | 0.20 | 4000 | always |
| tradespeople | Tradespeople labour (repairs, renovation) | credit | 0.20 | 1200 | always |
| minijob | Registered household mini-job | credit | 0.20 | 510 | always |
| childcare | Childcare | deduction | 0.80 | 4800 per child | children with age < 14 |
| private_school | Private-school tuition | deduction | 0.30 | 5000 per child | hasPrivateSchool |
| first_degree | First degree / initial training | deduction | 1.00 | 6000 | employment == student |
| party_donation_credit | Political-party donations (first portion) | credit | 0.50 | 825 per person | always |
| party_donation_deduction | Political-party donations (additional) | deduction | 1.00 | 1650 per person | always |
| energy_renovation | Energy renovation of own home | credit | 0.20 | 40000 per property (over 3 yrs) | housing == owner |
| home_office | Home-office days | deduction | 6 €/day | 1260 | homeOfficeDaysPerYear > 0 |
| commute | Commute (Entfernungspauschale) | deduction | 0.38 €/km/day | 4500 | commuteKm > 0 |

**Benefit math (in code):**
- `credit`: `benefit = min(rate × labourEur, cap)` — comes straight off the tax bill.
- `deduction`: `benefit = min(rate × amountEur, cap) × profile.marginalRate` — worth the marginal rate only.
- §35a credits (`household_services`, `tradespeople`, `minijob`) require `paidByTransfer == true`; otherwise benefit = 0.

`moves` (for §6.3): pay-tradesperson-by-transfer-this-year, file-2022-return-by-dec-31, bunch-medical-bills-this-year, donate-before-dec-31, apply-lohnsteuer-freibetrag-by-nov-30.

## 8. Tech

- Single web app, phone-width. Vite + React (or Next.js if someone already has it warm). Tailwind.
- State in memory + `localStorage`; no backend beyond one `/api/agent` route that calls the LLM.
- `perks.json` also served over a tiny MCP server so Cursor agents and the app read the same file (orchestration exhibit).
- Test fixtures: two sample invoices — `cleaner_transfer.txt` (counts) and `plumber_cash.txt` (does not count).

## 9. Demo script (90 s)

1. Home: "Lena — refund so far €0." Three recommended perks with € values. (S1)
2. Set "Household services" as goal → bar €0 / €4,000, rule sentence. (S2)
3. Upload `cleaner_transfer.txt` → agent card → **counted, +€144** → bar animates, header €144. (S3)
4. Upload `plumber_cash.txt` → **not counted: paid in cash** → "pay by transfer next time." (S3, the honest beat)
5. (Stretch) "Before Dec 31" card with 2 moves. (S4)
6. Close on the header number: "This is why she opens Taxfix in November."
